# Documentation review checklist

## Technical review

Verify methods, paths, schema types, requiredness, nullability, defaults, constraints, access, status codes, and side effects. Execute representative success and failure examples.

## Editorial review

Use reader-focused headings, consistent terminology, meaningful descriptions, and labelled excerpts. Remove vague recovery advice and unsupported claims.

## Workflow review

Start from a clean environment. Follow prerequisites, carry IDs forward, confirm the result, and test uncertain-outcome guidance.

## Interface review

Check links, search, mobile layout, keyboard access, focus, labels, copy controls, downloads, and readable code blocks.

## Evidence

Record checks run, results, skipped checks, unresolved questions, and reviewer ownership. A checklist is not proof that every requirement was met.
